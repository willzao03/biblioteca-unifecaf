1. Análise do Problema e do Protótipo

1.1 O Problema

A UniFECAF identificou a necessidade de uma plataforma digital centralizada para facilitar o acesso dos estudantes ao acervo bibliográfico, materiais acadêmicos e serviços da biblioteca. Antes desta interface, os alunos precisavam se deslocar fisicamente ou usar sistemas fragmentados para encontrar conteúdo de apoio ao aprendizado.

O desafio proposto foi transformar um protótipo de baixa fidelidade em uma interface web funcional, visualmente coerente e alinhada à identidade da instituição, utilizando exclusivamente HTML e CSS.

1.2 Análise do Protótipo de Baixa Fidelidade

O protótipo disponibilizado apresentou a seguinte estrutura:

  • Cabeçalho fixo com logotipo e menu de navegação (Biblioteca, Livros, Atividades, Contatos)
  • Hero banner com imagem grande de destaque e chamada principal
  • Seção "Sobre a Biblioteca" com texto descritivo, imagem e galeria de quatro fotos
  • Banner secundário com chamada para ação
  • Seção "Nossos Livros" em grid com seis cards (imagem, título, texto, botão)
  • Seção "As Unidades" com três unidades físicas, cada uma com imagem e descrição
  • Seção de Contato com informações e formulário
  • Rodapé com links institucionais
Decisão de expansão: além das seções do protótipo, foram adicionadas uma seção de Categorias (8 áreas do conhecimento) e uma de Serviços (4 diferenciais), enriquecendo a experiência sem romper a estrutura original.

2. Definição do Público-Alvo

2.1 Perfil Principal

O público primário é composto pelos estudantes de graduação e pós-graduação da UniFECAF, com perfil predominantemente jovem-adulto (18–35 anos), nativos digitais habituados a interfaces intuitivas e ao acesso móvel.

2.2 Perfis Secundários

2.3 Implicações no Design

O perfil jovem-adulto influenciou diretamente as decisões: hierarquia visual clara, textos objetivos, botões com área de toque adequada para mobile e uma paleta profissional que transmite confiança acadêmica sem ser intimidadora.

Justificativa das escolhas

  • Navy (#1a2e4a): cor primária institucional. Transmite autoridade, seriedade e confiança — valores essenciais de uma instituição de ensino superior.
  • Teal (#1e6f8e): cor de ação e interatividade. Deriva do azul, mantendo coerência, mas com vivacidade para botões e destaques.
  • Dourado (#f5a623): acento estratégico para badges e CTAs. Cria contraste energético sobre fundos escuros sem quebrar a identidade formal.
  • Gray-50 (#f8fafc): fundo alternado entre seções, criando ritmo visual sem bordas explícitas.

3.2 Tipografia

4. Justificativa das Principais Decisões Visuais

4.1 Header Sticky com Fundo Navy

O cabeçalho fixo em position: sticky garante que a navegação esteja sempre acessível durante o scroll. O fundo navy escuro cria contraste máximo com textos brancos, atendendo ao WCAG AA (4.5:1 mínimo — nossa relação é ~10.5:1).

4.2 Hero com Gradiente CSS Puro

Em vez de imagem de fundo (que pode falhar), o hero usa gradiente CSS com overlays decorativos via radial-gradient. Isso garante que a seção principal nunca apareça quebrada, mesmo sem conexão com internet.

4.3 Cards com Hover Elevado

Os cards aplicam transform: translateY(-6px) e aumento de box-shadow ao hover — padrão do Material Design que reforça interatividade sem JavaScript.

4.4 Alternância Consciente de Fundos

As seções alternam fundos: branco → cinza → navy → cinza → navy. Essa sequência guia o olhar ao longo da página e cria ritmo visual sem monotonia.

4.5 Layout Alternado nas Unidades

As três unidades usam layout imagem-texto alternado (esq/dir/esq), técnica editorial clássica que mantém atenção. Implementado via classe BEM .unidade-item--reverse com order no CSS.

4.6 Metodologia BEM no CSS

O CSS segue BEM (Block Element Modifier): .livro-card__title, .btn--primary. Facilita manutenção e evita conflitos de especificidade.

4.7 CSS Custom Properties como Design Tokens

Cores, espaçamentos e sombras estão definidas em :root. Alterar a identidade visual inteira requer modificar apenas esse bloco.

6. Estratégias de Responsividade

Abordagem Desktop First: layout base para telas largas, adaptado progressivamente via Media Queries.

BreakpointLarguraPrincipais mudanças
Tablet≤ 1024pxLivros 3→2 cols; Sobre empilhado; Contato coluna única
Mobile≤ 768pxHamburger ativo; Categorias 4→2; Livros 1 col; Serviços 1 col
Pequeno≤ 480pxLogo compactado; padding reduzido; Footer 1 coluna

6.1 Técnicas Utilizadas

  • CSS Grid com grid-template-columns — grids alteram colunas por breakpoint sem JS
  • clamp() — tipografia fluida entre mínimo e máximo automaticamente
  • Flexbox — nav, stats, listas lineares
  • aspect-ratio — proporções de imagem mantidas em qualquer largura
  • Menu hamburger — CSS + ~15 linhas de JavaScript

6.2 Prevenção de Quebras Comuns

  • Botões com white-space: nowrap — sem quebra de linha indesejada
  • Campos com width: 100% — nunca ultrapassam o container
  • Navbar mobile com position: absolute — não empurra o layout

7.2 Atributos ARIA

  • aria-label em botões e links sem texto descritivo
  • aria-expanded no hamburger, atualizado via JS
  • aria-labelledby associando seções aos títulos H2
  • aria-hidden="true" em emojis decorativos
  • role="banner", "navigation", "contentinfo"

7.3 Navegação por Teclado

  • Skip link "Pular para o conteúdo principal" — visível ao receber foco
  • :focus-visible com outline dourado de 3px em todos os interativos
  • @media (prefers-reduced-motion: reduce) — desativa animações quando o usuário prefere

8. Respostas às Questões Orientadoras

Como transformar um protótipo de baixa fidelidade em uma interface web moderna, responsiva e alinhada à identidade visual da UniFECAF?

Etapa 1 — Análise e interpretação

O protótipo foi analisado para identificar hierarquia de conteúdo, fluxo do usuário e seções obrigatórias. Cada bloco do wireframe foi mapeado a um componente HTML semântico específico.

Etapa 2 — Definição da identidade visual

A paleta foi derivada da identidade UniFECAF (navy como dominante), complementada por teal para ações e dourado para acentos. A Inter foi escolhida por legibilidade digital e versatilidade de pesos.

Etapa 3 — Construção com HTML semântico e CSS organizado

HTML com elementos semânticos corretos, CSS organizado em seções comentadas com Custom Properties e metodologia BEM — tornando o código coerente e manutenível.

Etapa 4 — Responsividade e refinamento

Breakpoints definidos pelo comportamento natural do conteúdo. clamp(), aspect-ratio e CSS Grid garantem adaptação fluida do smartphone ao monitor widescreen.

Conclusão: a interface resultante não apenas reproduz o protótipo — ela o expande com categorias, serviços e estatísticas, mantendo coerência visual total com a identidade UniFECAF. O resultado é uma plataforma que transmite credibilidade institucional com experiência moderna, acessível e responsiva.
