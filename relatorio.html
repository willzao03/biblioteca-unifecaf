1. Análise do Problema e do Protótipo

1.1 O Problema

A UniFECAF identificou a necessidade de uma plataforma digital centralizada para facilitar o acesso dos estudantes ao acervo bibliográfico, materiais acadêmicos e serviços da biblioteca. Antes do desenvolvimento desta interface, os alunos precisavam se deslocar fisicamente ou usar sistemas fragmentados para encontrar conteúdo de apoio ao aprendizado.

O desafio proposto foi transformar um protótipo de baixa fidelidade em uma interface web funcional, visualmente coerente e alinhada à identidade da instituição, utilizando exclusivamente HTML e CSS.

1.2 Análise do Protótipo de Baixa Fidelidade

O protótipo disponibilizado apresentou a seguinte estrutura:

  • Cabeçalho fixo com logotipo e menu de navegação (Biblioteca, Livros, Atividades, Contatos)
  • Hero banner com imagem grande de destaque e chamada principal
  • Seção "Sobre a Biblioteca" com texto descritivo, imagem e galeria de quatro fotos
  • Banner secundário com chamada para ação
  • Seção "Nossos Livros" em grid com seis cards (imagem, título, texto, botão)
  • Seção "As Unidades" com três unidades físicas, cada uma com imagem e descrição
  • Seção de Contato com informações e formulário
  • Rodapé com links institucionais
Decisão de expansão: além das seções do protótipo, foram adicionadas uma seção de Categorias e uma de Serviços, enriquecendo a experiência do usuário sem romper com a estrutura original proposta.

2. Definição do Público-Alvo

2.1 Perfil Principal

O público primário da Biblioteca Digital UniFECAF é composto pelos estudantes de graduação e pós-graduação da instituição, com perfil predominantemente jovem-adulto (18 a 35 anos), nativos digitais habituados a interfaces intuitivas e ao acesso móvel.

2.2 Perfis Secundários

Perfil Necessidade principal Como o site atende
Estudante de graduação Encontrar livros do currículo e pesquisa rápida Grid de livros, busca por categoria
Pós-graduando / pesquisador Acesso a bases de dados e periódicos Seção de serviços, bases de dados
Professor / coordenador Indicar obras e verificar disponibilidade Cards de livros com detalhes
Visitante externo Conhecer a instituição e serviços Seção Sobre, Unidades e Contato

2.3 Implicações no Design

O perfil jovem-adulto e mobile-first influenciou diretamente as decisões de design: hierarquia visual clara, textos objetivos, botões grandes com área de toque adequada, e uma paleta profissional que transmite confiança acadêmica sem ser intimidadora.

Justificativa das cores

  • Navy (#1a2e4a): cor primária da identidade UniFECAF. Transmite autoridade, seriedade e confiança — valores fundamentais de uma instituição de ensino superior.
  • Teal (#1e6f8e): cor de ação e interatividade. Deriva do azul institucional, mantendo coerência, mas com maior vivacidade para botões e destaques.
  • Dourado (#f5a623): acento estratégico para badges, CTAs e ícones de estatísticas. Cria contraste energético sobre os fundos escuros sem romper a identidade formal.
  • Gray-50 (#f8fafc): fundo alternado entre seções, criando ritmo visual sem exigir bordas explícitas.

4. Justificativa das Principais Decisões Visuais

4.1 Header Sticky com Fundo Navy

O cabeçalho fixo em position: sticky garante que a navegação esteja sempre acessível durante o scroll, padrão consagrado em interfaces modernas. O fundo navy escuro cria contraste máximo com os textos brancos, atendendo aos critérios WCAG AA de contraste mínimo (4.5:1).

4.2 Hero com Gradiente e Padrão de Pontos

Em vez de uma imagem de fundo (que pode falhar ao carregar), o hero utiliza um gradiente CSS puro com dois overlays decorativos: um padrão de pontos sutis via radial-gradient e manchas de cor radiais nos cantos. Isso garante que a seção principal nunca apareça "quebrada", mesmo em conexões lentas.

4.3 Cards com Hover Elevado

Os cards de livros e categorias aplicam transform: translateY(-6px) e aumento de box-shadow ao hover, criando a ilusão de elevação — padrão do Material Design que reforça a interatividade sem exigir JavaScript.

4.4 Seção de Serviços com Fundo Navy

A seção de serviços usa o fundo navy escuro para criar contraste visual e ritmo entre as seções de fundo claro. Essa alternância consciente de fundos (branco → cinza claro → navy → cinza claro → navy) guia o olhar do usuário ao longo da página sem monotonia.

4.5 Layout Alternado nas Unidades

As três unidades utilizam layout imagem-texto alternado (imagem à esquerda, direita, esquerda), técnica clássica de design editorial que mantém a atenção e evita a sensação de lista. Implementado via classes modificadoras BEM (.unidade-item--reverse) com order no CSS.

4.6 Metodologia BEM no CSS

O CSS segue a metodologia BEM (Block Element Modifier), que organiza os seletores em padrões legíveis como .livro-card__title e .btn--primary. Isso facilita a manutenção e evita conflitos de especificidade — decisão que demonstra maturidade técnica.

4.7 CSS Custom Properties como Design Tokens

Todas as cores, espaçamentos, tamanhos de fonte e sombras estão definidos como variáveis CSS (:root { --color-primary: #1a2e4a; }). Isso permite alterar a identidade visual inteira modificando apenas o bloco :root, tornando o código altamente manutenível.

5.1 Semântica HTML5

Cada seção utiliza elementos semânticos apropriados: <header>, <main>, <footer>, <section>, <article> e <nav>. Os títulos seguem hierarquia correta (H1 único no hero → H2 por seção → H3 para subcomponentes), permitindo leitura correta por tecnologias assistivas e melhor indexação por mecanismos de busca.

6. Estratégias de Responsividade

A abordagem adotada foi Desktop First — o layout base é construído para telas largas e progressivamente adaptado para telas menores via Media Queries. Foram definidos três breakpoints principais:

Breakpoint Largura Principais mudanças
Tablet ≤ 1024px Grid de livros: 3→2 colunas; seção Sobre empilhada; contato em coluna única; footer simplificado
Mobile ≤ 768px Menu hamburger ativado; hero sem altura mínima; categorias 4→2 colunas; livros 2→1 coluna; serviços 4→1 coluna; unidades empilhadas
Pequeno ≤ 480px Logo compactado; categorias mantidas em 2 colunas com padding reduzido; footer em coluna única

6.1 Técnicas Utilizadas

  • CSS Grid com grid-template-columns responsivo — os grids alteram o número de colunas via media queries sem JavaScript
  • clamp() para tipografia fluida — os títulos se redimensionam proporcionalmente entre o valor mínimo e máximo sem breakpoints específicos
  • Flexbox para componentes lineares (nav, cards de estatísticas, itens de lista)
  • max-width + margin-inline: auto no container principal para centering automático
  • Menu hamburger em CSS puro com animação via transform, controlado por JavaScript mínimo (~15 linhas)
  • aspect-ratio para manter proporções de imagens consistentes em qualquer largura

6.2 Imagens Responsivas

Todas as imagens utilizam max-width: 100%, object-fit: cover e aspect-ratio fixo. Isso garante que nenhuma imagem distorça ou quebre o layout em telas menores.

6.3 Prevenção de Quebras Comuns

  • Textos longos: uso de line-height generoso e max-width nos parágrafos de subtítulo
  • Botões: white-space: nowrap para evitar quebra de linha indesejada
  • Formulário: campos com width: 100% que nunca ultrapassam o container
  • Navbar mobile: position: absolute sobre o conteúdo, sem empurrar o layout

7. Princípios Básicos de Acessibilidade

7.1 Contraste de Cores (WCAG AA)

As combinações de cor críticas atendem ao critério WCAG 2.1 nível AA (contraste mínimo 4.5:1 para texto normal):

TextoFundoContraste (aprox.)Status
Branco #fffNavy #1a2e4a~10.5:1✅ AAA
Branco #fffTeal #1e6f8e~4.8:1✅ AA
Navy #1a2e4aDourado #f5a623~7.2:1✅ AAA
Gray-700 #334155Branco #fff~9.7:1✅ AAA

7.2 Atributos ARIA e Semântica

  • aria-label em todos os links e botões com texto não descritivo
  • aria-expanded no botão do menu mobile, atualizado via JavaScript
  • aria-controls associando o botão ao menu que ele controla
  • aria-labelledby associando cada seção ao seu título H2
  • aria-hidden="true" em elementos decorativos (emojis, ícones)
  • aria-required="true" nos campos obrigatórios do formulário
  • role="banner", role="navigation", role="contentinfo" nos landmarks principais

7.3 Navegação por Teclado

  • Skip link visível ao receber foco: "Pular para o conteúdo principal" — permite que usuários de teclado/leitores de tela ignorem a navegação repetida
  • :focus-visible com outline dourado de 3px em todos os elementos interativos
  • Todos os links e botões são elementos nativos HTML com foco automático correto

7.4 Imagens

Todas as imagens possuem atributo alt descritivo. Imagens puramente decorativas usam aria-hidden="true". O atributo loading="lazy" melhora a performance sem prejudicar o acesso ao conteúdo.

7.5 Movimento Reduzido

A media query @media (prefers-reduced-motion: reduce) desativa todas as transições e animações para usuários que configuram essa preferência no sistema operacional, respeitando necessidades de pessoas com epilepsia ou sensibilidade a movimento.

Nota: a validação completa de acessibilidade requer testes manuais com tecnologias assistivas (NVDA, VoiceOver) e auditoria especializada. As medidas implementadas atendem os critérios WCAG 2.1 nível AA verificáveis automaticamente.

8. Respostas às Questões Orientadoras

Como transformar um protótipo de baixa fidelidade em uma interface web moderna, responsiva e alinhada à identidade visual da UniFECAF?

A transformação do protótipo em interface funcional seguiu um processo estruturado em quatro etapas:

Etapa 1 — Análise e interpretação

O protótipo foi analisado para identificar a hierarquia de conteúdo, o fluxo do usuário e as seções obrigatórias. Cada bloco do wireframe foi mapeado a um componente HTML semântico específico, garantindo que a estrutura de informação fosse preservada na transição para o código.

Etapa 2 — Definição da identidade visual

A paleta foi derivada da identidade institucional da UniFECAF (azul navy como cor dominante), complementada por teal para ações interativas e dourado para acentos de destaque. A tipografia Inter foi escolhida por sua legibilidade digital e versatilidade nos múltiplos pesos necessários para a hierarquia visual.

Etapa 3 — Construção com HTML semântico e CSS organizado

O HTML foi estruturado com elementos semânticos corretos, garantindo acessibilidade e SEO. O CSS foi organizado em seções comentadas e utiliza Custom Properties como sistema de design tokens, tornando o código coerente e manutenível. A metodologia BEM foi aplicada para nomear classes de forma previsível.

Etapa 4 — Responsividade e refinamento

Os breakpoints foram definidos a partir do comportamento natural do conteúdo (onde o layout "quebra" naturalmente), não apenas por dispositivos específicos. Técnicas modernas como clamp(), aspect-ratio e CSS Grid garantem que o layout se adapte fluidamente a qualquer largura de tela, do smartphone ao monitor widescreen.

Conclusão: a interface resultante não apenas reproduz o protótipo — ela o expande com componentes adicionais (categorias, serviços, estatísticas no hero), mantendo total coerência visual e funcional com a identidade UniFECAF. O resultado é uma plataforma que transmite credibilidade institucional e oferece experiência de uso moderna, acessível e responsiva.
